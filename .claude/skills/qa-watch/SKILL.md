# Мовчазний напарник

Ярослав тестує руками. Ти дивишся на те, чого не видно на екрані, і **мовчиш, поки все добре**.

## Головне правило

Ти не коментуєш кожну ітерацію. Кожен тік без знахідок — це `noop`.
Пиши тільки коли є **нова** проблема. Повторення тієї самої помилки — не новина.

## Налаштування (один раз на старті)

1. `mcp__claude-in-chrome__tabs_context_mcp` — визнач вкладку, яку тестує Ярослав.
   Якщо вкладок кілька й незрозуміло — спитай один раз, далі не перепитуй.
2. Скажи одним рядком: за якою вкладкою стежиш і що вважатимеш проблемою.
3. Запусти цикл: `/loop 3m /qa-watch` (або без інтервалу — тоді сам обирай паузу
   2–5 хв; частіше не треба, ти нічого не пропустиш — логи буферизуються).

## Що перевіряти на кожному тіку

Одним блоком, паралельно:

- `read_console_messages` з `pattern` для фільтра шуму — шукай `error`, `Uncaught`,
  `Unhandled`, `Failed to`, `TypeError`, `ReferenceError`.
- `read_network_requests` — статуси >= 400, `requestfailed`, запити довші за 3 с.

## Про що сигналити

| Сигналити | Мовчати |
|---|---|
| Нова JS-помилка | Та сама помилка вдруге |
| 5xx на будь-якому запиті | 401 на ендпоінті логіну під час логіну |
| 4xx на запиті, який UI проковтнув без повідомлення | 404 на favicon, sourcemap, аналітиці |
| Запит > 3 с | Довгі SSE / websocket / polling-зʼєднання |
| Бита картинка з реальним src | Блокування рекламних доменів |
| `Mixed Content`, `CORS`, `CSP` | Попередження бібліотек рівня `warn` |

Перед тим як сигналити — звір із попереднім тіком. Тримай у голові список уже
повідомлених помилок, щоб не дублювати.

## Формат сигналу

Коротко, одразу з дією:

```
Помилка, якої не видно на екрані:
POST /api/cart/apply-promo -> 500 (щойно, 14:32:06)
Консоль: TypeError: Cannot read properties of undefined (reading 'discount')

UI помилку не показав. Схоже, ти щойно застосовував промокод — повтори,
підтвердь, і я одразу оформлю це в баг.
```

Якщо Ярослав каже «так, це баг» — переходь на skill `qa-bug` і збери повний репорт
із уже зібраних даних, не змушуючи його повторювати кроки.

## Завершення

Коли він каже «стоп», «досить», «закінчив» — зупини цикл і видай підсумок сесії:
скільки тіків, які проблеми знайдено, які лишились без реакції.
