# Перевірка верстки

## Разовий аудит

```
node qa-toolkit/responsive/responsive.js <url> [ще url...] [опції]
```

Опції: `--set mobile|tablet|desktop|all`, `--viewports 360,768,1440`,
`--storage auth.json` (для сторінок під логіном), `--tap-min 44` (AAA замість AA),
`--headed`, `--no-shots`, `--out <dir>`.

Скрипт сам знаходить: горизонтальний скрол із точним «зайвим» розміром у px,
конкретні елементи, що вилазять за край (з CSS-шляхом), обрізаний текст,
тач-таргети менші за 24px, биті картинки, помилки консолі та запити 4xx/5xx.

Результат — папка з `report.md`, `report.json` і скріншотами.

### Як подавати результат

Не переказуй увесь звіт. Прочитай `report.md` і видай:

1. Одним рядком — на яких ширинах чисто, на яких ні.
2. Проблеми, згруповані **за причиною**, а не за ширинами: якщо один і той самий
   елемент вилазить на 320, 360 і 390 — це одна проблема, а не три.
3. Для кожної — CSS-шлях, на скільки px і на якій ширині починається.
4. Скріншоти проблемних ширин прочитай через Read і подивись сам: скрипт ловить
   структурні дефекти, але накладання блоків і зламану сітку видно тільки очима.

Відсортуй за серйозністю: горизонтальний скрол на мобільному — це завжди баг;
тач-таргет 22px — залежить від того, чи це основна дія.

## Візуальна регресія

Еталон знімається **до** змін (або на проді), порівняння — після.

```
set QA_URLS=https://site/a,https://site/b
set QA_WIDTHS=390,1280
npx playwright test --config qa-toolkit/visual/playwright.config.js --update-snapshots   # еталон
npx playwright test --config qa-toolkit/visual/playwright.config.js                       # порівняння
npx playwright show-report qa-toolkit/visual/report                                        # дифи
```

`QA_MASK` — селектори через кому, які треба замалювати перед знімком: банери,
лічильники, поточна дата, аватарки. Без цього будуть хибні дифи щоразу.
`QA_STORAGE` — storageState для авторизованих сторінок.

Еталони лежать у `qa-toolkit/visual/baseline/` і комітяться — інакше немає з чим
порівнювати завтра.

### Коли диф червоний

Спершу подивись на картинку діфу сам і скажи, це справжня регресія чи «поплив»
динамічний контент. Якщо друге — додай селектор у `QA_MASK` і перезніми, не змушуй
Ярослава дивитись на шум.

## Порада

Після будь-якої знахідки одразу пропонуй `qa-bug` — у звіті вже є все, що треба
для репорту: скріншот, точні px, CSS-шлях, ширина.
