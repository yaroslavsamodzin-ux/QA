# Тестування на реальному Android

Інструмент: `qa-toolkit\android\adb.ps1`. Це обгортка над офіційним adb —
без root, без сторонніх застосунків на телефоні.

Запуск завжди так:
```
powershell -ExecutionPolicy Bypass -File qa-toolkit\android\adb.ps1 <команда>
```

## Перед першим використанням

Якщо `devices` каже, що пристрою немає — не вважай це поломкою. Перевір по порядку
і скажи Ярославу, що саме зробити:

1. `qa-toolkit\android\setup.ps1` — якщо adb взагалі не встановлений. Кладе його в
   `%LOCALAPPDATA%\platform-tools`: без прав адміністратора і без root на телефоні.
2. На телефоні: Налаштування → Про телефон → 7 тапів по «Номер збірки».
3. Налаштування → Для розробників → «Налагодження USB» увімкнено.
4. Кабель у режимі передачі даних (не «тільки зарядка»).
5. На екрані телефона — «Дозволити налагодження USB?» → Дозволити.

Бездротово (Android 11+): `adb.ps1 pair <ip:порт> <код>`, далі `adb.ps1 connect <ip:порт>`.
Код і порт беруться в Налаштування → Для розробників → Бездротове налагодження.

## Команди

| Команда | Навіщо в тестуванні |
|---|---|
| `info` | модель, Android, роздільність, щільність — у баг-репорт |
| `shot [файл]` | скріншот реального екрана, не емуляції |
| `rec <сек>` | відео відтворення бага одразу у вкладення |
| `open <url>` | відкрити тестовану сторінку в браузері телефона |
| `app <package>` | запустити застосунок |
| `tap x y` / `swipe` / `text` / `key` | пройти сценарій, не торкаючись телефона |
| `ui` | дерево UI з координатами й розмірами |
| `audit` | **сам знаходить** тач-таргети < 48dp і елементи за межами екрана |
| `log [фільтр]` | помилки застосунку в реальному часі |
| `inspect` | як відкрити DevTools для Chrome на телефоні |

## Типові сценарії

**«Подивись, як виглядає на телефоні»**
```
adb.ps1 open https://стенд/сторінка
adb.ps1 shot
```
Прочитай скріншот через Read і опиши, що не так. Далі `adb.ps1 audit` — воно
знайде дрібні кнопки й вилізлі за екран елементи з точними розмірами.

**«Пройди сценарій на телефоні»**
Спочатку `ui`, щоб дізнатись координати елементів із їхніх `bounds`, потім
`tap`/`text`/`key`. Після кожного кроку — `shot`, щоб бачити, де ти опинився.
Не тапай наосліп.

**«Чому падає застосунок»**
`adb.ps1 clearlog`, далі попроси відтворити, далі `adb.ps1 log` і шукай
`FATAL EXCEPTION`, `ANR`, `E/AndroidRuntime`.

**Веб на телефоні з повним доступом до консолі**
`adb.ps1 inspect` і далі через `chrome://inspect/#devices` на ПК. Тоді доступні
звичайні console/network інструменти для сторінки, що відкрита на телефоні.

## Правила

- Введення тексту через `text` не працює з кирилицею — для українського тексту
  використовуй буфер обміну або DevTools. Скажи про це прямо, не вдавай, що ввів.
- Не відкривай на телефоні нічого, крім тестових стендів, без прямого прохання.
- Дані з `shot`, `ui`, `log` — це вміст екрана користувача. Не викладай їх нікуди
  за межі відповіді без його згоди.
- Файли складаються в `qa-toolkit/android/out/` (не потрапляють у git).
